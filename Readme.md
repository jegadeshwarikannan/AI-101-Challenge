
# AI 101 — 101 Days. One Journey. Real Skills.

> A 101-day journey to learn, build, experiment, and develop practical skills in Applied AI and Automation.

## About This Project

AI 101 is my personal, hands-on learning challenge focused on building practical Applied AI and Automation skills.

Rather than only consuming tutorials, I want to understand the concepts, implement them, solve problems, document my experiments, and build projects that demonstrate what I can actually do.

This repository serves as my public learning journal and a record of my progress throughout the journey.

## My Background

I am a Robotics & Automation engineering graduate with experience in:

- Python and Java
- Spring Boot, REST APIs, and MySQL
- OpenCV and computer vision
- YOLO and introductory machine learning
- Git and software development fundamentals

I am using this challenge to strengthen my existing knowledge and develop practical skills in AI application development, intelligent automation, and AI engineering.

## The Goal

By the end of 101 days, I aim to:

- Understand the fundamentals of modern AI and large language models.
- Build applications using LLMs, embeddings, and retrieval-augmented generation (RAG).
- Develop tool-using AI workflows and agent-based applications.
- Evaluate AI outputs and improve reliability.
- Explore multimodal AI, including text and image-based applications.
- Build, test, and deploy AI-powered applications.
- Understand practical machine learning workflows.
- Complete an independent capstone project.
- Build a public record of my learning, experiments, and completed work.

## Learning Philosophy

**Learn → Build → Test → Explain → Reflect → Repeat**

My focus is not on completing the maximum number of tutorials. It is on understanding what I learn and being able to apply it independently.

Every learning stage should include practical implementation, experimentation, and documentation.

## How I Will Track Progress

For each learning session, I will aim to record:

1. What I learned.
2. What I implemented.
3. What worked and what failed.
4. What I can explain without referring to notes.
5. What I need to revisit.

Progress will be tracked in [progress.md](progress.md).

## What Counts as Proof?

A Git commit records a change to the repository. It does not, by itself, prove mastery.

My evidence of learning will come from:

- Working code and reproducible experiments.
- Meaningful commits and documented changes.
- Tests and evaluation results.
- Explanations written in my own words.
- Projects that I can demonstrate and explain independently.
